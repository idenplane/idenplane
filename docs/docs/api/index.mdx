# API Reference

Idenplane provides a comprehensive REST API for managing authentication, users, clients, and realms. The API follows REST conventions and uses JSON for request and response bodies.

## Base URL

Idenplane is self-hosted, so the base URL is your server's `BASE_URL`:

```
Local:      http://localhost:3000
Your host:  https://auth.example.com
```

## API Versions

The admin API is not versioned yet. It is served under `/admin/...`; nothing is served under `/api/v1`. See [Versioning and Support](../project/versioning-and-support.md).

## Swagger/OpenAPI

Every Idenplane server publishes its own complete, always-current API reference, generated from the code it runs:

| Path | What it is |
|---|---|
| `/api` | Swagger UI, for exploring and trying every endpoint |
| `/api-json` | The OpenAPI document as JSON, for client generators and diff tools |

For a local server, open `http://localhost:3000/api`. Authorize with your admin API key (`x-admin-api-key`) or a bearer token to try the admin endpoints.

The pages in this section, and the [`openapi.yaml`](https://github.com/idenplane/idenplane/blob/main/docs/docs/api/openapi.yaml) in the repository, describe the core endpoints only: realms, users, clients, groups, roles, the OAuth and OpenID Connect endpoints, instance usage, and health. For everything else, such as auth flows, webhooks, organizations or client certificates, use the server's `/api`.

## Authentication

Every Admin API endpoint (`/admin/...`) needs one of these:

- **The admin API key**, the `ADMIN_API_KEY` the server was started with, in the `x-admin-api-key` header:

  ```bash
  curl "http://localhost:3000/admin/realms" \
    -H "x-admin-api-key: $ADMIN_API_KEY"
  ```

- **An admin user's access token**, the one the admin console signs in with, as a bearer token:

  ```bash
  curl "http://localhost:3000/admin/realms" \
    -H "Authorization: Bearer $ADMIN_ACCESS_TOKEN"
  ```

:::note
`X-Api-Key` is a different header. It carries a service account's API key, not the admin key, and the Admin API does not accept it.
:::

## API Endpoints Overview

### Authentication & OAuth

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/realms/:realmName/protocol/openid-connect/token` | POST | Token endpoint (all OAuth grants) |
| `/realms/:realmName/protocol/openid-connect/auth` | GET | Authorization endpoint |
| `/realms/:realmName/protocol/openid-connect/userinfo` | GET | UserInfo endpoint |
| `/realms/:realmName/protocol/openid-connect/logout` | GET/POST | Logout endpoint |
| `/realms/:realmName/protocol/openid-connect/revoke` | POST | Token revocation (RFC 7009) |
| `/realms/:realmName/protocol/openid-connect/token/introspect` | POST | Token introspection (RFC 7662) |
| `/realms/:realmName/protocol/openid-connect/certs` | GET | JWKS |
| `/realms/:realmName/.well-known/openid-configuration` | GET | Discovery document |

### Realms

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/admin/realms` | GET | List all realms |
| `/admin/realms` | POST | Create a new realm |
| `/admin/realms/:realmName` | GET | Get realm details |
| `/admin/realms/:realmName` | PUT | Update a realm |
| `/admin/realms/:realmName` | DELETE | Delete a realm |
| `/admin/realms/:realmName/export` | GET | Export realm configuration |
| `/admin/realms/import` | POST | Import realm configuration |

| `/admin/realms/:realmName/users/:userId/offline-sessions` | GET | List offline sessions |

## HTTP Status Codes

| Code | Description |
|------|-------------|
| `200` | Success |
| `201` | Created |
| `204` | No Content (successful delete) |
| `400` | Bad Request (invalid parameters) |
| `401` | Unauthorized (missing or invalid credentials) |
| `403` | Forbidden (insufficient permissions) |
| `404` | Not Found |
| `429` | Too Many Requests (rate limited) |
| `500` | Internal Server Error |

## Rate Limiting

Several limits apply:

- **Every request**: a global throttle of `THROTTLE_LIMIT` requests (default 100) per `THROTTLE_TTL` milliseconds (default 60000) per client, in each server process.
- **Admin API key**: 60 requests per minute and 1000 per hour per client IP (`ADMIN_API_KEY_RL_PER_MINUTE`, `ADMIN_API_KEY_RL_PER_HOUR`).
- **Token endpoint**: per-IP (20 per minute, 200 per hour) and per-client (60 per minute, 1000 per hour) limits, only when the realm's `rateLimitEnabled` is on. It is off by default; the numbers are realm settings.

Rate limit information is included in response headers:

```http
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
X-RateLimit-Reset: 1620000000
```

## Error Response Format

All errors follow a consistent format:

```json
{
  "statusCode": 400,
  "message": ["email must be an email"],
  "error": "Bad Request",
  "timestamp": "2026-11-16T10:00:00.000Z"
}
```

`message` is a string, or an array of strings for validation errors. A request body with a field the endpoint does not know is rejected with `400` (`property x should not exist`). The OAuth endpoints answer with the OAuth error format instead (`{"error": "...", "error_description": "..."}`).

## Pagination

The user list takes `page` and `limit` (default 20) query parameters:

```bash
GET /admin/realms/master/users?page=1&limit=20
```

and returns the page with the total count:

```json
{
  "users": [...],
  "total": 150
}
```

Most other list endpoints, such as realms and clients, return a plain JSON array without pagination.
